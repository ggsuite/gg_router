# راهنمای README برای DNA

برای README یک مخزن DNA این راهنما را دنبال کنید — لایه‌ای که مخزن‌های دیگر
آن را در `dna/_dna.json` خود فهرست می‌کنند. نام آن `dna_*` یا `dna-*` است،
یا `dna/_dna.json` آن `mustOverride` را اعلام می‌کند. خوانندهٔ آن API
فراخوانی نمی‌کند: می‌خواهد بداند مخزنش با افزودن این لایه چه به دست می‌آورد.

از [راهنمای README](./readme-guide.md) این موارد اعمال می‌شوند: صفحهٔ اول،
انگیزه، پیوند دادن، نشان‌ها، Markdown، هر دو زبان و بررسی. مثال،
محدودیت‌ها و وضعیت اعمال نمی‌شوند: بخش استفاده راه‌اندازی را نشان می‌دهد و
بخش دامنه محدودیت‌ها را نام می‌برد.

## کپی کردن قالب <a id="copy-the-template"></a>

- `doc/en/templates/readme-dna-template.md` را در `README.md` کپی کنید، یا
  README موجود را بر اساس آن بازبینی کنید
- هر بخشی را که این لایه چیزی برایش ندارد حذف کنید

## بگویید لایه چه می‌کند <a id="say-what-the-layer-does"></a>

- با یک جمله شروع کنید: مخزن با افزودن این لایه چه به دست می‌آورد
- همان جمله را به عنوان `description` در `pubspec.yaml` و `package.json`
  به کار ببرید
- موضوعی را که لایه مالک آن است نام ببرید، نه سازوکار پشت آن را
- انگیزه را بنویسید: لایه کدام مشکل مخزن‌های مصرف‌کننده را حل می‌کند

## نشان دهید چطور استفاده می‌شود <a id="show-how-to-use-it"></a>

- راه‌اندازی را درست بعد از انگیزه نشان دهید، خواننده می‌خواهد آن را امتحان
  کند
- بگویید فایل‌ها در مخزن مصرف‌کننده کجا قرار می‌گیرند، مثلاً `dna/doc/` در
  `doc/`، `dna/dot-claude/` در `.claude/`، `dna/scripts/` در `scripts/`
- نشان دهید آنچه عرضه می‌کند چطور استفاده می‌شود، مثلاً فرمان یک skill یا
  یک اسکریپت و آنچه چاپ می‌کند
- پیش‌نیازهای سخت را نام ببرید، مثلاً Node.js برای یک اسکریپت

## فهرست آنچه لایه عرضه می‌کند <a id="list-what-the-layer-ships"></a>

- برای راهنماها، قالب‌ها، skillها، اسکریپت‌ها و پیکربندی هر کدام بخشی جدا
  در نظر بگیرید
- هر فایل را با مسیرش زیر `dna/` و یک خط دربارهٔ هدفش نام ببرید؛ پوشه‌ای از
  فایل‌های کمکی را به صورت یکجا نام ببرید، مثلاً `dna/scripts/functions/`
- یک skill را با فرمانی که کاربر تایپ می‌کند نام ببرید، مثلاً `/translate`
- بگویید کدام راهنما یک اسکریپت را فراخوانی می‌کند

## دامنه را نام ببرید <a id="name-its-scope"></a>

- آنچه را لایه عمداً به لایه‌های دیگر یا به مخزن واگذار می‌کند نام ببرید

## لایه‌هایی را که بر آن‌ها بنا شده نام ببرید <a id="name-the-layers-it-builds-on"></a>

- لایه‌های والد را از `dna/_dna.json` فهرست کنید، هر کدام با پیوند به
  مخزنش
- بگویید هر والد چه سهمی دارد، نه فقط نامش را
- اگر لایه والدی ندارد، بگویید که مستقل (orthogonal) است؛ helix، پایهٔ
  همهٔ لایه‌ها، والد به شمار نمی‌آید
- بخش‌هایی را که در یک والد گسترش می‌دهد، و تگی را که به کار می‌برد، نام
  ببرید

## مستندسازی متغیرها <a id="document-the-variables"></a>

- همهٔ متغیرهای `dna/_vars.json` را فهرست کنید
- معنای هر کدام را بگویید؛ مقدار را فقط جایی بیاورید که توضیح می‌دهد چرا
  متغیر وجود دارد
- بگویید کدام‌ها را مخزن مصرف‌کننده باید خودش تنظیم کند، یعنی آن‌هایی که
  `mustOverride` در `dna/_dna.json` مشخص می‌کند

## به‌روز نگه داشتن <a id="keep-it-current"></a>

- در بخش توسعه بگویید که فقط `dna/` ویرایش می‌شود، هرگز کپی‌هایی که تست
  می‌نویسد
- README را در همان تغییری به‌روز کنید که یک فایل DNA را اضافه یا حذف می‌کند
- `node scripts/check-readme.js` را اجرا کنید؛ در مخزن DNA این اسکریپت
  علاوه بر این هر فایل `dna/`، متغیر و لایهٔ والدی را که README به آن اشاره
  نمی‌کند گزارش می‌کند
